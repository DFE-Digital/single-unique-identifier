## 1. Architecture Boundaries (Domains)

- **CSC system provider**
  Providers of systems holding information relevant to provision of children's
  social care (CSC). Can be a public sector agency maintaining an in-house system or a
  private sector supplier of a provided system.

- **DfE**
  Department for Education central matching, routing, and subscription orchestration services.

- **NHS England**
  External NHS digital health infrastructure providing patient identity and event messaging (PDS, MNS, MESH).


## 2. Component Inventory

### 2.1 External Entities

- **`Agency A, B, C, etc.`** (`CSC system provider`)
  Local agencies using the CSC system provider's database to store information relevant to child social care.

### 2.2 Data Stores

- **`[D1]` PDS Patients** (`NHS England`)
  Personal Demographics Service database containing authoritative patient identities.

- **`[D2]` MNS Subscriptions** (`NHS England`)
  Message Notification Service registry tracking active subscriptions for demographic/GP changes.

- **`[D3]` MESH mailbox** (`NHS England`)
  Message Exchange for Social Care and Health mailbox holding pending patient change messages.

- **`[D4]` Children** (`CSC system provider`)
  CSC system provider database of child records across participating agencies.

### 2.3 Processes

- **`[P01]` Match children without an identifier to an NHS number** (`CSC system provider`)
  Identifies unlinked local records and coordinates matching requests with DfE.

- **`[P02]` Match demographics to NHS number** (`DfE`)
  Core matching engine querying NHS PDS and establishing identity links.

- **`[P03]` Search for a patient** (`NHS England`)
  Executes search queries against PDS.

- **`[P04]` Subscribe for patient record changes** (`NHS England`)
  Registers interest in future updates for matched NHS numbers in MNS.

- **`[P05]` Record new patient record change message** (`NHS England`)
  Detects PDS mutations matching active subscriptions and posts change messages.

- **`[P06]` Update child record, based on patient record change event** (`CSC system provider`)
  Applies NHS number or GP practice updates back to the system provider child store.

- **`[P07]` Forward patient record change events** (`DfE`)
  Ingests events, acknowledges receipt, and relays relevant updates to system providers.

- **`[P08]` Read available events** (`NHS England`)
  Polls or consumes queued messages from the MESH mailbox.

- **`[P09]` Acknowledge events** (`NHS England`)
  Confirms receipt of messages to remove them from the MESH mailbox.

- **`[P10]` Clean duplicate subscriptions** (`DfE`)
  Identifies and reconciles duplicate or obsolete MNS subscriptions.

- **`[P11]` Read all subscriptions** (`NHS England`)
  Exports current active subscription records from MNS.

- **`[P12]` Delete subscriptions** (`NHS England`)
  Removes target subscription IDs from MNS.


## 3. End-to-End Operational Pipelines

### Pipeline 1: Child Ingestion, Demographic Matching & Change Subscription

Handles initial ingestion from local agencies, matching against PDS, returning NHS numbers, and establishing ongoing change subscriptions.

1. `Agency A, B, C, etc.` → `[D4] Children`
   *Payload*: `Child demographics`
2. `[D4] Children` → `[P01] Match children`
   *Payload*: `Child demographics`
3. `[P01] Match children` → `[P02] Match demographics`
   *Payload*: `Child demographics`
4. `[P02] Match demographics` → `[P03] Search for a patient`
   *Payload*: `Child demographics`
5. `[D1] PDS Patients` → `[P03] Search for a patient`
   *Payload*: `FHIR Patients`
6. `[P03] Search for a patient` → `[P02] Match demographics`
   *Payload*: `NHS numbers and GP codes`
7. `[P02] Match demographics` → `[P01] Match children`
   *Payload*: `NHS numbers and GP codes`
8. `[P01] Match children` → `[D4] Children`
   *Payload*: `NHS numbers and GP codes`
9. `[P02] Match demographics` → `[P04] Subscribe for changes`
   *Payload*: `NHS Numbers`
10. `[P04] Subscribe for changes` → `[D2] MNS Subscriptions`
    *Payload*: `Subscriptions for NHS number and GP changes on a patient`


### Pipeline 2: Patient Record Change Ingestion & CSC System Provider Notification

Monitors demographic and GP changes published by NHS England and propagates them back into system provider records.

1. `[D1] PDS Patients` → `[P05] Record new change message`
   *Payload*: `Patient record changes`
2. `[D2] MNS Subscriptions` → `[P05] Record new change message`
   *Payload*: `Active patient record subscriptions`
3. `[P05] Record new change message` → `[D3] MESH mailbox`
   *Payload*: `Patient record change messages`
4. `[D3] MESH mailbox` → `[P08] Read available events`
   *Payload*: `Patient record change messages`
5. `[P08] Read available events` → `[P07] Forward events`
   *Payload*: `Patient record change events`
6. `[P07] Forward events` → `[P09] Acknowledge events`
   *Payload*: `Event acknowledgements`
7. `[P09] Acknowledge events` → `[D3] MESH mailbox`
   *Payload*: `Message acknowledgements`
8. `[P07] Forward events` → `[P06] Update child record`
   *Payload*: `NHS number or GP code change notifications`
9. `[P06] Update child record` → `[D4] Children`
   *Payload*: `NHS numbers and GP codes`


### Pipeline 3: Subscription Hygiene & De-duplication

Periodic maintenance routine to detect duplicate or orphaned subscriptions and keep MNS tidy.

1. `[D2] MNS Subscriptions` → `[P11] Read all subscriptions`
   *Payload*: `Active patient record subscriptions`
2. `[P11] Read all subscriptions` → `[P10] Clean duplicate subscriptions`
   *Payload*: `Active patient record subscriptions`
3. `[P10] Clean duplicate subscriptions` → `[P12] Delete subscriptions`
   *Payload*: `Subscription IDs`
4. `[P12] Delete subscriptions` → `[D2] MNS Subscriptions`
   *Payload*: `Subscription IDs`
